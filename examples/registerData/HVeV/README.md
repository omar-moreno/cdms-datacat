# HVeV data registration

This is a summary of the effort to register data from the first HVeV run to the data catalog.

# renaming/moving files

The data catalog expects/requires data to conform to a path specification.  The expected path specification is documented at https://confluence.slac.stanford.edu/display/CDMS/SuperCDMS+Data+Organization#Data-datatype.

Originally the HVeV data did not conform to this spec; code in the `copyFiles` directory addresses this.  What we did was create CSV files that had the format

```
old_file_path, spec_file_path
```

and then operated on those files.  These files were quite large and were stored in a separate repository, https://gitlab.com/supercdms/DataHandling/previousPaths.

# reading in metadata and registering the files

Metadata for the HVeV experiment was kept in google sheets and there was not an attempt to match the columns with the metadata fields used by the data catalog.  Nonetheless there was good agreement and we were able to find the expected metadata by using the recorded fields and the filenames.

The files `readCSVAR70.py` and `readCSVPMT.py` read in the data from the google spreadsheet, grab the appropriate metadata, and register the file ("dataset" in Data Catalog terms) associated with each row of metadata

# registering all the files

After a while, discussion turned up an error: the metadata in the google spreadsheet did not apply to one file, it applied to all files between the timestamps of each entry.

The files `addDSfromCSV.py` and `addDSfromCSVPMT.py` address this - you'll see that they start by pulling in all the entries in the CSV files generated by the "rename files to comply with the data catalog specification" rather than using the google spreadsheet to drive file registration.
